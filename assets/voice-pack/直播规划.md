# 长辈祝福屋 · 首播测试规划 v1

## 1. 目标

- 做一场 60 分钟的本地干跑，验证画面、语音、队列、挂件和 OBS 采集链路。
- 画面：竖屏 1080×1920，3D 祝福现场 + 左下角财源宝宝挂件 + 底部祝福卡。
- 人群：中老年观众，语气温暖、慢一点、少用网络梗。
- 通过标准：60 分钟不崩、语音不重叠、队列持续出福、OBS 不断流、至少完成 3 次完整互动。

## 2. 技术准备

| 项目 | 设置 |
|---|---|
| 主程序 | `http://127.0.0.1:8080/` |
| 输出方向 | 竖屏 1080×1920 |
| 数据桥 | `ws://127.0.0.1:8765`，需要真实直播间号 |
| 浏览器 | Chrome / WebView2，保持前台，不要最小化 |
| OBS 场景 1 | 主画面：1080×1920 浏览器源 |
| OBS 场景 2 | 近景：头像/福牌特写，可选 |
| OBS 场景 3 | 离开/维护提示 |
| OBS 场景 4 | 故障提示，不放隐私信息 |
| 音频 | 系统音频采集；语音约 -16 LUFS；机器音效比语音低 6–8dB |
| 字体 | 中文字体已加载，避免 OBS 里出现方框 |

开播前检查：

1. 服务 8080 返回 200。
2. 页面 WebGL 正常，3D 场景不是黑屏。
3. 左下角挂件能循环播放，不黑屏。
4. 语音包 24 条能播放，音量一致。
5. 数据桥 8765 已连接，或明确接受本地演示模式。
6. OBS 录制 60 秒，回看画面和声音。
7. 电脑关闭自动锁屏、休眠、系统通知。

## 3. 60 分钟流程

### -10～0 分钟：开播前

- 打开主程序和数据桥，确认直播间号。
- 播放 `greet_01`、`greet_03` 试音。
- OBS 录 30 秒，检查竖屏构图、字幕、挂件位置。
- 关闭无关通知，锁定音量。

### 0～5 分钟：开场

- `greet_01`：亲爱的爷爷奶奶，欢迎来到直播间……
- `greet_03`：欢迎各位长辈来到直播间……
- 画面保持主场景，不急着连发。
- 口播补充：今天做什么、怎么参与、评论 666 会发生什么。

### 5～15 分钟：暖场

- 有人进场：`enter_01` 或 `enter_02`。
- 有人评论：`interact_03`，再触发一张小福牌。
- 无互动时每 60–90 秒补一句 `greet_02` / `enter_03`，不要连续重复同一句。
- 目标：让观众看懂“评论 → 排队 → 写福 → 出福气值”的闭环。

### 15～35 分钟：主互动

- 礼物：`gift_01`–`gift_04` 轮流感谢。
- 关注：`interact_01`；点赞：`interact_02`。
- 打印开始：`print_01`；打印过程可用 `print_04` 安抚等待。
- 打印完成：`print_03`，配合福气值展示。
- 礼物高峰期不打断当前福牌；语音排队，不叠加。

### 35～45 分钟：留人峰值

- 重复讲规则，但换说法：`interact_03`、`interact_04`。
- 用长句 `close_02` 或祝福语拉停留。
- 至少完成一次“进场 → 评论 → 写福 → 完成”的完整演示。

### 45～55 分钟：收尾前

- 提醒关注：`interact_04`。
- 提醒天凉添衣：`close_03`。
- 预告下一场：`close_04` 只播一次，不要提前透支。

### 55～60 分钟：收尾

- `close_01`：今天直播就到这里……
- `close_02`：感谢陪伴……
- `close_04`：下次再见……
- 关闭数据桥，停止 OBS，保存录制文件。

## 4. 事件与语音优先级

优先级从高到低：

1. 礼物感谢：`gift_01`–`gift_04`
2. 进场欢迎：`enter_01`–`enter_04`、`greet_02`
3. 打印完成：`print_03`
4. 打印开始：`print_01`
5. 关注/点赞/评论：`interact_01`–`interact_04`
6. 通用安抚：`print_04`
7. 收尾：`close_01`–`close_04`

规则：

- 同一句至少间隔 3 分钟再重复。
- 同一条语音不叠加；当前语音没播完，下一条进队列。
- 礼物高峰时最多排 3 条，超出只显示字幕。
- 带昵称的动态播报继续走现有 `GiftSpeech`；固定语音包只负责通用话术。

## 5. 无互动兜底 cue

没有人说话时，按顺序循环，间隔 60–90 秒：

1. `greet_02`
2. `enter_03`
3. `interact_03`
4. `print_04`
5. `close_03`

不要连续播放两条“欢迎”，也不要在 10 秒内连播三条。

## 6. 合规与话术边界

- 不说“包治百病”“一定长寿”“保证发财”等绝对承诺。
- 不索要住址、电话、身份证、银行卡等隐私。
- 不冒充本人或第三方声音；AI 合成语音按平台要求标注。
- 不评价观众外貌、家庭矛盾、疾病细节。
- 遇到医疗、投资、法律问题，统一回复“请咨询专业人士”。
- 遇到攻击性弹幕，不接话，直接跳过或拉黑。

## 7. 故障处理

| 故障 | 处理 |
|---|---|
| 数据桥断开 | 页面回本地演示，继续播；不要在直播中反复重连 |
| 语音播报失败 | 保留字幕；切系统语音；不要静音硬撑 |
| 3D 画面黑屏 | 先刷新页面；仍黑则切 OBS 场景 4，不要露桌面 |
| 帧率过低 | 画质降到“标准/极速”，关反射或降 MSAA |
| 队列卡住 | 点“换下一位”；仍卡则刷新页面，演示数据会重建 |
| OBS 断流 | 优先恢复推流，画面暂切维护页 |
| 麦克风/系统音异常 | 切备用音频源，先保证人声可听 |

## 8. 测试计划

### A. 画面

- 主页面 1440×900 截图。
- 竖屏 1080×1920 场景模式截图。
- 检查挂件、祝福卡、品牌牌、队列文字不重叠。

### B. 音频

- 24 条文件存在、可解码、时长 3–8 秒。
- 合集响度约 -16 LUFS，峰值低于 -1 dBFS。
- ASR 回查无明显吞字；重点检查“常伴/常在、事事、稍坐、添衣”。

### C. 交互

- 运行规则演示，确认评论、爱心、啤酒、棒棒糖分别生成 1/1/2/3 张福牌。
- 连续 10 分钟不手动介入，确认队列不空转、不重复、不堆积。

### D. 真实直播

- 需要直播间号后才能测数据桥。
- 先测“进场 + 评论 + 爱心”三类事件，再测礼物高峰。

## 9. 接入语音包的下一步

当前语音包在 `voice-pack/`，不在打印程序静态目录内，页面不能直接访问。接入时：

1. 把 `voice-pack/mp3/` 复制到 `3d-printer-live/assets/voice-pack/`。
2. 加一个极小的播放模块：按事件读取 mp3，播完再取下一条。
3. 固定话术优先用语音包；带昵称/礼物名的动态话术回退 `GiftSpeech`。
4. 播放失败回退系统语音，不阻塞福牌队列。
5. 先接 `greet_01`、`enter_01`、`gift_01`、`print_01`、`print_03`、`close_01` 六条做小流量测试。
